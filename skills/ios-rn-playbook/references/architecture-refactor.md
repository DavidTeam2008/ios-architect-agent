## 一、架构重构与开发

### 工作原则

1. 改动前先执行代码勘探：使用 Grep/Glob 定位相关模块，梳理依赖关系后输出改造方案
2. 严格遵循团队编码规范，OC/RN 代码遵循团队规范
3. 桥接层改动必须同时考虑：接口兼容性、线程安全、内存管理、异常兜底
4. 涉及底层基建改动时，必须评估对所有业务线 RN 页面的影响范围

### 重构场景覆盖

- 底层 OC 基建模块化拆分与解耦
- 定制 RN 框架的版本升级与能力增强
- 业务线 RN 页面的架构优化与性能改造
- OC 与 RN 边界的重新划分与桥接层重构
- 新业务模块在混合架构下的落地设计

---

### 专项六：混合架构（棕地）集成规范

#### 桥接层设计原则

- 架构基线：新架构下以 TurboModule / Fabric 组件 / JSI HostObject 为桥接边界；旧 RCTBridge 模块需评估迁移
- 接口稳定：原生模块接口向下兼容，避免频繁变更影响所有业务线
- 线程安全：所有原生模块明确调用线程，JS 线程与主线程边界清晰
- 内存可控：原生模块实例生命周期明确，避免循环引用与内存泄漏
- 异常兜底：原生侧异常不导致 JS 层崩溃，JS 侧异常有原生降级方案

#### 生命周期同步规范

- 页面生命周期：原生页面与 RN 页面生命周期事件双向同步
- 应用前后台：前后台事件透传至 JS 层，业务侧可做资源释放
- 内存警告：原生 `didReceiveMemoryWarning` 同步至 JS 层，触发分级释放

#### Bundle 加载策略

- 首屏预加载：首页及高频页面 Bundle 提前初始化
- 按需加载：低频业务 Bundle 进入页面前再加载
- 版本兜底：线上 Bundle 加载失败时，自动回退至内置兜底版本
