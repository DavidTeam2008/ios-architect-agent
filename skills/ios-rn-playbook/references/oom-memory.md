> 何时读我：FOOM / BOOM / 内存增长 / 低内存机型集中问题。
> 不适用：普通崩溃（有堆栈）→ crash-apm.md；白屏 → white-screen.md。
> 必须先有：无崩溃日志、终止前内存水位、前后台状态、页面/操作路径。
> 产出：OOM 分型 + 归因 + 分级治理 + 验证指标。

#### 2. OOM 问题归因规则

1. 先确认类型：通过「无崩溃日志 + 终止前内存水位 + 前后台状态」判定 FOOM / BOOM
2. 再判断模式：
   - 缓慢增长型 → 优先排查内存泄漏、缓存未释放
   - 突发峰值型 → 优先排查大对象分配、大图解码、批量数据处理
   - 后台常驻型 → 优先排查后台任务、后台缓存、常驻线程
3. 关联场景：发生页面、操作路径、停留时长、列表滑动状态

### 专项二：OOM 全链路治理体系

#### 1. OOM 分类与检测体系

##### 分类定义

| 类型         | 全称             | 发生场景       | 主要原因               |
| ---------- | -------------- | ---------- | ------------------ |
| **FOOM**   | Foreground OOM | 前台使用时被系统杀死 | 前台内存占用超过系统阈值       |
| **BOOM**   | Background OOM | 后台时被系统杀死   | 后台常驻内存过高，Jetsam 回收 |
| **VM OOM** | 虚拟内存耗尽         | 地址空间耗尽     | 内存映射过多、堆碎片严重       |

##### 检测方案

- **Jetsam 日志解析**：系统杀进程日志，可100%确认OOM与被杀时内存值，准确率最高
- **内存水位监控**：`mach_task_self()` + `task_info` 周期采样，结合生命周期状态推断OOM
- **MetricKit**：iOS 26 及以前用 MXMetricPayload / MXDiagnosticPayload；iOS 27 起两者已在 27.3 SDK 标记 deprecated，改用 MetricManager 的 MetricReport / DiagnosticReport（metricReports/diagnosticReports，AsyncSequence），作为线上补充证据。
- **FOOM 判定规则**：无崩溃日志、非主动退出、非用户划杀，且终止前内存高于阈值

#### 2. 分层排查方法论

1. **场景确认**：FOOM/BOOM、发生页面与操作路径、影响机型系统范围、是否低内存机型集中
2. **原生内存排查**：Leaks 查泄漏、Allocations 查堆增长、VM Tracker 查非堆内存、Core Animation 查渲染内存
3. **RN 内存排查**：JS 堆内存快照、原生视图生命周期对比、图片缓存监控、Bridge / JSI 持有对象与 HostObject 生命周期对比
4. **系统机制排查**：不同iOS版本Jetsam阈值、后台内存限制、可用内存差异

#### 3. 分级治理手段

##### 防御层：三级内存水位预警

| 级别       | 触发阈值     | 执行动作                                  |
| -------- | -------- | ------------------------------------- |
| **黄色预警** | 系统阈值 50% | 释放非核心图片缓存、清理过期磁盘缓存                    |
| **橙色预警** | 系统阈值 70% | 释放所有离屏图片缓存、销毁不可见页面预加载、降低列表渲染质量        |
| **红色预警** | 系统阈值 85% | 释放所有可重建资源、关闭非核心后台任务、触发页面降级、通知 JS 侧 GC |

##### 优化层：四大重点领域

- **图片内存优化**：按控件尺寸解码、分级缓存上限、滑动降质加载、WebP/HEIF 格式
- **列表滑动峰值优化**：Cell 高度缓存、滑动暂停非紧急任务、减少离屏渲染、复用池上限控制
- **RN 专项优化**：Bundle 按需加载、页面销毁彻底清理、桥接数据批量传输、长列表虚拟化
- **原生基建优化**：数据库缓存限制、日志内存上限、单例生命周期管理、大文件分段读取

##### 兜底层：极端场景降级

- 低内存机型默认关闭高内存消耗功能
- 高内存场景自动降级动画、图片质量、预加载数量
- OOM 现场快照保留：分配堆栈、当前页面、操作路径

#### 4. 验证与防劣化

- 核心指标：FOOM 率、BOOM 率、平均内存、峰值内存、泄漏数
- CI 内存回归测试：核心路径内存增长超限自动拦截
- 版本内存专项：重点页面进出对比、长时间压测
- 知识库沉淀：每次结案根因与修复方案入库
